The Technology Behind ResilioChain

Why we chose each framework, what it does for the business, and where it lives in our code — written so anyone can follow, no coding required.

ResilioChain watches for supply‑chain shocks — a typhoon, a port closure, sanctions — and in seconds finds a safe, allowed, reliable backup supplier. To do that well it uses a handful of specialist tools, each explained below with a real business example.

1. LangGraph — the team manager

The manager that runs our five AI helpers in a disciplined relay race.

What it is

Our app isn't one big robot — it's a team of five AI helpers (Supervisor, Impact Assessor, Sourcing, Compliance, Planner), each with one job. LangGraph decides who works next, passes the problem down the line, and knows when to loop back or stop.

Why we chose it

Left to talk freely, AI agents wander, repeat themselves, or get stuck. LangGraph turns the process into a clear flowchart with rules: "after Sourcing finds candidates, always send them to Compliance; if Compliance rejects everyone, try again — but no more than 3 times."

Business payoff: Reliability (same process every time), auditability (who decided what, when), and safety rails that stop endless loops or runaway spend.
Example: Typhoon Yagi alert arrives → Supervisor ("how bad?") → Impact Assessor ("23 orders, 48,200 units at risk") → Sourcing ("3 backups") → Compliance ("reject the unethical one") → if a backup fails ethics, LangGraph automatically loops back to Sourcing, up to 3 tries → then the Planner writes the brief.
Where in the code:
  • backend/app/agents/graph.py — the flowchart itself: the five helpers wired with "if this, go there" rules (build_graph()), the retry loop, and the stop conditions.

2. AWS Bedrock (Claude) — the reasoning brain

The AI that actually reads and understands the disruption.

What it is

Bedrock is Amazon's secure service for running top‑tier AI. We use it to run Claude (from Anthropic) — the model that reads and understands language. When an alert says "Typhoon Yagi has closed the Port of Tanjung Pelepas for 72 hours," Claude grasps that it's severe, which supplier is hit, and what it means.

Why we chose it

  • Enterprise trust — runs inside AWS; our data stays in our cloud.
  • No vendor lock‑in — a thin adapter means we can swap the AI vendor without rewriting the app.
  • Keeps working even offline — if the AI is unreachable, a built‑in deterministic stand‑in keeps a live demo from crashing.
Business payoff: Human‑level understanding of messy text — at machine speed and scale, with enterprise security and a graceful safety net.
Example: We use a stronger Claude model for the hardest thinking (Supervisor + Planner) and a faster, cheaper model for routine helpers — balancing quality and cost, like staffing a team with seniors and juniors.
Where in the code:
  • backend/app/llm/bedrock.py — the single doorway to the AI; the vendor is swappable and the offline fallback lives here.
  • backend/app/config.py — where we assign the stronger vs. faster model per helper.

3. Bedrock AgentCore Runtime — the engine room

Amazon's managed, secure hosting purpose‑built for AI agents.

What it is

AgentCore Runtime is the secure, professionally‑run "building" where our AI team lives and takes requests — instead of us renting a bare server and wiring the plumbing ourselves.

Why we chose it

  • Security done right — uses an AWS execution role, so we don't scatter secret keys around.
  • Scales on demand — one alert or a thousand, no re‑architecting.
  • Purpose‑built for agents — designed for exactly this multi‑step AI workflow.
Business payoff: The difference between a hackathon prototype and something an IT department would actually approve for production.
Example: An external system calls it with {"alert_text": "Typhoon Yagi has closed the port…"} and gets back the full decision — winner supplier, confidence score, cost impact — as a clean summary.
Where in the code:
  • backend/agentcore_app.py — the official "front door"; wraps our LangGraph workflow so AWS can host and invoke it.
  • backend/requirements-agentcore.txt — the ingredients list for that hosted engine.

4. MongoDB $graphLookup — tracing the ripple effect

Follows the chain of connections to reveal everything a disruption hits.

What it is

A MongoDB feature that follows chains of connections inside your data. One broken link ripples outward: a down supplier → the orders that depend on it → the products those orders feed. $graphLookup walks that chain in a single step.

Why we chose it

The "ripple effect" is the whole point of supply‑chain risk. Doing it by hand is slow and error‑prone. MongoDB does the traversal inside the database, where the data already lives — fast and complete.

Business payoff: The moment a supplier goes down, you instantly see every order at risk and the exact total you must re‑source — nothing missed.
Example: SUP‑001 is down. $graphLookup traces every active order that depends on it and sums the shortfall to exactly 48,200 units — the number the rest of the workflow must cover.
Where in the code:
  • backend/app/mcp_tools/blast_radius_query.py — the "blast radius" tool, running $graphLookup over orders → suppliers.
  • backend/app/graphrag.py — a second, multi‑hop $graphLookup used by the plain‑English Q&A feature.

5. MongoDB $vectorSearch — finding suppliers by meaning

Matches on meaning, not exact words — so the right backups surface.

What it is

A normal search matches exact words. $vectorSearch matches meaning. It knows a supplier described as "automotive microcontroller assembly" is a strong match for "car‑grade MCU components" — even though the words differ.

Why we chose it

Real supplier catalogs never use identical wording, so a keyword search would miss good backups. Meaning‑based search finds the right candidates — and MongoDB runs it right alongside our business data.

Business payoff: Better backups found faster, with a safety rule baked in — we filter by real capacity at the database level, so a supplier that can't cover the volume is never even suggested. That rule is enforced by code, not the AI.
Example: With the shortfall known (48,200 units), Sourcing asks: "find suppliers similar to what we need — but ONLY ones that can make at least 48,200 units/month, NOT the down supplier, and NOT in the disrupted region." It returns the top 3, each with a similarity score.
Where in the code:
  • backend/app/mcp_tools/supplier_vector_search.py — meaning‑based supplier search with a hard capacity filter and region/supplier exclusions.
  • backend/app/mcp_tools/compliance_rag_query.py — the same technique to pull relevant compliance‑policy passages.
  • backend/app/mcp_tools/_vs.py — shared helper that runs the search and patiently retries on free‑tier rate limits.
⚙️

6. Atlas autoEmbed — let the database do the AI translation

MongoDB automatically turns text into searchable "meaning" for us.

What it is

To search by meaning, text must first be turned into numbers that capture its meaning (an "embedding"). autoEmbed means MongoDB Atlas does that translation automatically — both when we store a supplier and when we search — so we never run it ourselves.

Why we chose it

The alternative ("explicit" mode) means we generate every embedding, store it, and keep it in sync — more code, more ways to break. With autoEmbed the database owns it. (We kept manual mode available as a backup, controlled by one setting.)

Business payoff: Less custom code, fewer moving parts, and no risk of search "translations" going stale — the platform keeps them current.
Example: We just save a supplier's description text; Atlas + Voyage turn it into searchable meaning behind the scenes, and translate each search query the same way so both sides speak the same language.
Where in the code:
  • backend/app/db/indexes.py — vector indexes defined as type: "autoEmbed", telling Atlas to manage the embeddings with Voyage AI.
  • backend/app/config.py — the single switch (EMBEDDING_MODE = autoembed | explicit).
🧬

7. Voyage AI — turning words into "meaning"

The best‑in‑class specialist behind the "search by meaning" magic.

What it is

Voyage AI is a top‑rated embedding provider — the specialist that performs the "text → meaning‑numbers" translation that powers $vectorSearch. MongoDB partners with Voyage and uses it under the hood for autoEmbed.

Why we chose it

Your search is only as good as these "meaning" translations. Voyage's models rank highly for retrieval accuracy, and Atlas integrates them natively — top‑tier relevance without gluing on a separate service.

Business payoff: More accurate supplier and policy matches — the search genuinely understands the domain, so the backups it surfaces are the right ones.
Example: Voyage is what lets "automotive‑grade MCU and sensor components" find "car electronics controller manufacturing" as a match.
Where in the code:
  • backend/app/db/indexes.py — Voyage (voyage-4) named as the model Atlas uses for autoEmbed.
  • backend/app/mcp_tools/_embed.py — the direct Voyage client, used only in the optional manual mode.
  • backend/app/config.py — Voyage API key and model settings.
💬

8. GraphRAG — ask the disruption a question in plain English

Builds a map of who‑relates‑to‑whom, then answers only from that map.

What it is

GraphRAG reads unstructured disruption text, builds a little map (a "knowledge graph") of who relates to whom, then answers questions using only that map. RAG means the AI answers strictly from facts we retrieved — so it can't make things up.

Why we chose it

Leaders don't want to read raw data — they want to ask: "What does Typhoon Yagi affect, and how?" GraphRAG turns messy text into a connected map and gives a grounded, cited answer with traceable reasoning.

Business payoff: A plain‑English Q&A layer over the disruption, backed by the actual relationships in the data — no hallucinations.
Example: Ask "What is impacted by Typhoon Yagi?" — GraphRAG finds the starting points (Yagi, Tanjung Pelepas, SUP‑001) and hops across the map (Yagi affects Malaysia, SUP‑001 located_in Malaysia, orders depend_on SUP‑001), then answers in sentences citing those links.
Where in the code:
  • backend/app/graphrag.py — the full canonical GraphRAG: extract_graph() builds the map, query_graph() does the multi‑hop traversal, answer() writes the grounded reply.
  • backend/app/api/graphrag.py — exposes it as an API the dashboard can call.
🔌

9. Real MCP server (FastMCP) + Python fallback

A universal, standards‑based toolbox that never dies mid‑demo.

What it is

MCP (Model Context Protocol) is the emerging industry standard for how AI agents plug into tools — like USB for devices. We expose our five MongoDB tools as a proper MCP server using FastMCP, and we built a fallback: if the server isn't running, the app quietly uses the same tools directly in‑process.

Why we chose it

  • Interoperability & future‑proofing — our tools speak the MCP standard, so any MCP‑compatible AI could use them.
  • Same logic, two ways in — the MongoDB code is written once and shared, so the answer is identical over the network or in‑process.
  • Never dies mid‑demo — automatic fallback means a down server or network hiccup can't break the workflow.
Business payoff: A standards‑based, interoperable, and bulletproof integration layer — enterprise‑ready today, ready to plug into the wider AI ecosystem tomorrow.
Example: In a live demo, Sourcing calls supplier_vector_search. If the MCP server is up, the request goes over the standard protocol; if not, the app instantly and invisibly runs the same MongoDB search in‑process. Either way the audience sees the right answer — no error, no drama.
Where in the code:
  • backend/app/mcp_server.py — the real MCP server (FastMCP), exposing tools and resources.
  • backend/app/mcp_client.py — the smart client that tries MCP first and automatically falls back on any failure.
  • backend/app/mcp_tools/* — the single shared implementation both paths use.

The takeaway for leadership

ResilioChain pairs the best reasoning AI (Claude on AWS Bedrock) with the best operational database for this job (MongoDB Atlas). LangGraph keeps the AI team disciplined and auditable; AgentCore hosts it securely at enterprise scale. MongoDB does the heavy lifting where the data lives — tracing the ripple effect ($graphLookup) and finding backups by meaning ($vectorSearch, powered by Voyage AI and autoEmbed). GraphRAG lets anyone ask the disruption questions in plain English, and our MCP + fallback design makes the whole thing interoperable and impossible to break in a demo. Every choice trades a hackathon shortcut for something an enterprise would actually ship. 🛡️
